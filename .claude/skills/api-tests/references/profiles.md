# Профили ручек бэкенда (чёрный ящик)

Транспорт один — REST поверх FastAPI, поэтому разбиение идёт не по транспорту,
а по **профилю**: что у ручки специфичного в обвязке и какие категории кейсов
из этого обязательно следуют.

Профиль ручки объявляется в шапке плана и в поле `profile` каждого кейса
в `cases.yaml`.

| Профиль | Признак | Примеры |
|---|---|---|
| `http` | обычная синхронная ручка | `tests/user/test_user_endpoints.py` |
| `sse` | поток событий | три ручки в `/api/v1/ai/*` |
| `llm` | ответ формирует агент | analyze / tailor / cover-letter |
| `job` | результат готовит фоновый arq-worker | те же ai-ручки, poll-часть |
| `ratelimit` | поведение определяется бакетом | `tests/user/test_user_endpoints.py` |

Профили сочетаются: `POST /api/v1/ai/tailor` — одновременно `http`, `llm` и `job`.
Брать обязательные категории кейсов из **каждого** подходящего профиля.

Профиля `email` **нет и не будет**: почтового приёмника на стенде нет. Кейс,
которому нужно письмо, помечается ⚠️/✖ в плане и в код не идёт (STAND-005).

---

## `http` — обычная ручка

**Обвязка.** Фикстуры `api` + `auth`; данные сидятся через API (`user`, `seed_resume`).

**Категории кейсов, обязательный минимум:**

| Категория | Ожидание |
|---|---|
| Happy path | 2xx + ассерты на **значения** полей ответа, не на их наличие |
| Отсутствует обязательное поле | 422 от Pydantic |
| Невалидный тип / формат поля | 422 |
| Нет токена | 401 |
| Чужой объект | **404, не 403** (AUTH-002); второй пользователь — второй регистрацией |
| Невалидный UUID в пути | 404, не 422 (AUTH-003) |
| Наблюдаемое следствие | проверяется той ручкой, которая его отдаёт (DB-003) |

**Ловушка.** Ветка хендлера легко подменяется валидацией схемы: тест на «нет
обязательного поля» может уйти в 422 на схеме и не дойти до ветки, которую проверяет
(ASSERT-004). Если проверяется именно ветка хендлера — тело запроса должно проходить
схему (пример: токен сброса пароля ≥16 символов).

**Ловушка e-mail.** email-validator бэкенда режет special-use TLD (`.test`,
`.invalid`, `.localhost`): «валидный незнакомый адрес» — это `@example.com`
с uuid в локальной части, а `.test`-адрес даст 422 вместо ожидаемой ветки.

## `sse` — поток событий

| Ручка |
|---|
| `GET /api/v1/ai/stream/{analysis_id}` |
| `GET /api/v1/ai/tailor/{job_id}/stream` |
| `GET /api/v1/ai/cover-letter/{cover_letter_id}/stream` |

**Семантика (контракт про поток не говорит ничего):**

- первый кадр всегда снапшот текущего статуса — опоздавший подписчик сразу отрисуется;
- поток закрывается на `done` или `error`.

**Обвязка.** Только фикстура `sse` — дедлайн и лимит событий встроены (SSE-005).
Worker на стенде реальный: события идут через настоящий Redis pub/sub, ничего
подменять не нужно и нельзя.

**Категории кейсов, обязательный минимум:**

| Категория | Ожидание |
|---|---|
| Поздний подписчик | задание уже `done` → первый кадр `done`, поток закрывается сразу (SSE-002) |
| Полный цикл | последовательность `queued → running → done`, поток закрыт (SSE-003) |
| Прогресс | `progress` не убывает и заканчивается на 100 (SSE-004) |
| Чужое задание | 404 до открытия потока |
| Невалидный UUID | 404 |
| Ошибка задания | кадр `error`, поток закрывается — если ошибку можно поднять через API; нельзя → ✖ |

Ветка «нет Redis → 503» из белого ящика — **✖**: на стенде Redis не выключить
(STAND-003, второй профиль ради одной ветки не заводится).

Ретрай SSE-теста — только на падении инфраструктуры стенда, никогда на ассертах.

## `llm` — ответ формирует агент

**Обвязка.** Моков нет. Детерминизм — конфигурация стенда: пустые
`ANTHROPIC_API_KEY` / `ZAI_API_KEY` включают эвристический fallback всех агентов
(STAND-004). Ответы воспроизводимы между прогонами.

**Категории кейсов:**

| Категория | Ожидание |
|---|---|
| Признак движка | `model_used == "heuristic"` в ответе — стенд сконфигурирован верно |
| Happy path | структура результата и инварианты, **не дословный текст** (ASSERT-006) |
| Диапазоны и типы | `0 ≤ scores[k] ≤ 100`, списки непустые, у элементов есть обязательные поля |
| Резюме нестандартной формы | пустые секции, отсутствующие поля — ответ формируется, не падает |

Ветка «провайдер вернул ошибку» — снаружи не поднимается (ключей нет, провайдера
нет) → **✖** в плане.

**Ловушка.** Качество генерации LLM здесь не проверяется — это осознанное решение:
API-тесты проверяют контракт и оркестрацию, качество модели — отдельный набор.

## `job` — фоновая задача

**Обвязка.** Worker на стенде реальный (arq в своём контейнере). In-process
fallback белого ящика недоступен. Наблюдение — только через API:

- статус — `poll_until("/api/v1/ai/analyze/{id}", headers=auth)` с дедлайном (JOB-001);
- события — фикстура `sse`.

**Категории кейсов:**

| Категория | Ожидание |
|---|---|
| Немедленный ответ POST | `status in {"queued", "running", "done"}` — worker реальный, точный статус — гонка (JOB-002) |
| Переход до `done` | `poll_until` доводит до `done`, финальные поля заполнены |
| Ошибка задачи | статус `error` + `error_code` — если ошибку можно поднять через API; нельзя → ✖ |
| Согласованность | статус в poll-ручке и финальный кадр SSE не противоречат друг другу |

Идемпотентность воркера, гонки внутри arq, «задания нет в БД» — внутрипроцессные
сценарии, снаружи не наблюдаются → **✖**, покрываются юнитами в репозитории бэкенда.

---

## `ratelimit` / доступ

**Обвязка.** Настоящий Redis стенда; флаша нет и не нужно. Изоляция:

- IP-бакеты — уникальный `X-Forwarded-For` на тест, его даёт фикстура `api` (RATE-001);
- пер-JWT-бакеты — уникальный пользователь на тест (RATE-002).

Размеры бакетов и окна — из `stand/.env.stand` (RATE-006), не из дефолтов бэкенда.

**Категории кейсов:**

| Категория | Ожидание |
|---|---|
| Исчерпание бакета | 429 **и** `Retry-After` ≥ 1 (RATE-003) |
| Независимость бакетов | выжечь один — соседний ещё пускает (RATE-004) |
| Лимит раньше хендлера | 429 там, где хендлер вернул бы 404/401 (RATE-005) |
| Ключ бакета | разные пользователи / разные IP не делят счётчик |

Ветка «лимитера нет → no-op» — конфигурация, не API → **✖**, юниты бэкенда.

**Анонимные сессии.** Ручек нет: в бэкенде остались только заголовок `X-Anon-Session`
в CORS и `ANON_SESSION_TTL_DAYS` в конфиге. Кейсы «анонимного флоу» не проектировать.
