# Ship — отгрузка изменений

Детерминированная последовательность: ветка → коммит → пуш → текст MR.

**MR этот скилл не создаёт.** Платформа — SourceCraft (`ssh.sourcecraft.dev`),
CLI для неё в системе нет, `gh` тут не работает. Скилл доводит до запушенной ветки
и печатает готовое описание — создаёт MR человек.

## Шаг 1. Показать, что отгружаем

```bash
git status --short
git diff --stat
```

Покажи пользователю список файлов. Незапланированные файлы в диффе (мусор, временные
файлы, чужие правки) — **остановиться и спросить**, а не коммитить.

`.claude/tmp/` в коммит не идёт: это рабочее состояние пайплайна.

**Дифф `contracts/` в тестовом MR** — отдельный вопрос пользователю: снапшот
контракта правится осознанно (FORBID-010), его изменение в MR с тестами должно
быть либо согласовано, либо вынесено.

## Шаг 2. Ветка

Уже на ветке не `main` — работать на ней. Иначе создать:

```bash
git switch -c <тип>/<краткое-описание>
```

Префикс по содержимому: `tests/` — тесты, `infra/` — стенд и обвязка,
`fix/` — исправление. Описание — латиницей, через дефис, без номера задачи.

**На `main` не коммитить.**

## Шаг 3. Прогнать проверки

Перед коммитом — то же, что гоняет CI (стенд поднят снаружи, `STAND_URL` указывает
на него):

```bash
uv run pytest -q
python scripts/openapi_snapshot.py --check
```

Красное — **не коммитить**. Показать вывод пользователю и остановиться.

## Шаг 4. Коммит

```bash
git add <конкретные файлы>
git commit -m "<сообщение>"
```

`git add -A` не использовать — добавлять перечисленные файлы. Сообщение: одна строка
по-русски, что сделано и зачем, без списка файлов.

## Шаг 5. Пуш

```bash
git push -u origin HEAD
```

Вывод `git push` показать пользователю целиком: SourceCraft печатает в нём ссылку
на создание MR — это то, что человеку нужно кликнуть.

## Шаг 6. Описание MR

Собрать текст и **напечатать его в ответе** — не в файл, чтобы можно было скопировать.

Для тестового MR формат задан в
[`api-tests/references/mr-comment.md`](../api-tests/references/mr-comment.md).
Для остальных — коротко: что сделано, зачем, что проверено.

В описании только факты из фактического прогона. Не было прогона — не писать его результат.

## Правила

- Коммит и пуш — только когда пользователь этого попросил (в том числе через `/api-tests`,
  где `/ship` — последний шаг).
- Красные тесты не отгружаются.
- MR не создаётся автоматически: нет CLI и нет права публиковать за пользователя.
- Force-push и перезапись чужих веток — запрещены.
